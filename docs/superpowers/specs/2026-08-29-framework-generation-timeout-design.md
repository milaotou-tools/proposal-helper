# 框架生成等待上限调整设计

## 目标

避免申报书框架在已经开始流式输出后，因两分钟总等待上限被中断；不改变模型、提示词、页面、重试或生成内容。

## 范围

- 将 AI 请求的最长总时限从 120,000 毫秒调整为 300,000 毫秒（5 分钟）。
- 流式请求额外使用 120,000 毫秒的“静默时限”：每收到任意一个模型数据块就重置该时限；仅连续 120 秒没有任何数据时才中止。
- 非流式请求只使用 5 分钟总时限，因为它不会逐块返回数据。

## 不在范围内

- 不更换 `deepseek-v4-pro` 模型。
- 不关闭或降低模型思考模式。
- 不调整提示词、生成栏目、前端文案或自动重试逻辑。
- 不修改 8083 线上版本。

## 工作方式

框架生成已采用流式响应：模型开始返回正式正文后，前端立即显示收到的内容。流式读取器每次收到数据块都会重置静默时限，包含模型思考阶段产生但当前页面不展示的流数据。因此模型仍在工作时不会因开始计时后的第 120 秒被主动取消；总时间到 5 分钟或完全静默持续 120 秒，才会由既有控制器中止。

## 验收标准

1. `streamChatCompletion` 与 `createChatCompletion` 均使用 300,000 毫秒的最长总时限。
2. `streamChatCompletion` 在每次读取到流数据时重置 120,000 毫秒静默时限。
3. 两个函数的模型、请求体、提示词和页面逻辑保持不变。
4. TypeScript 类型检查通过。
